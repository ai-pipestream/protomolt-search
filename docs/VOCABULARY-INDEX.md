# Vocabulary index (Rust side)

The Rust realization of the vocabulary listener designed in
`grpc-opennlp-analysis/VOCABULARY-LISTENER.md` (the sidecar repo is the
authoritative design doc). The split by role: the Java sidecar
**calculates** (term identity is counted exactly as the analysis pipeline
produced it); turbovec-search **accumulates, stores, and aggregates** —
inline in the ingest path, from the AnalyzeStream responses the node
already consumes to build postings. No new gRPC channel, no proto changes.

## What it counts

Every successfully analyzed document on the AddDocuments AnalyzeStream
path feeds two channels (src/vocab.rs):

| Channel | Source | Identity |
|---|---|---|
| TERMS | `term_vectors` of the response, with frequencies | exactly the BM25 index identity |
| TOKENS | raw `tokens[].text` of the response | surface forms, pre-normalization |

Per channel per window: a HyperLogLog (p=14, distinct-term cardinality), a
count-min sketch (depth 5, width 2^17, point frequencies), a space-saving
top-K heavy-hitter list (default K=1024), and doc/occurrence counters —
~11 MiB per channel, bounded by configuration, never by corpus size.

The unary `Analyze` path (query analysis, extra-field captions) is never
counted: query text does not enter corpus statistics. The hook lives in
`AnalyzeStream::next()` (src/analyzer.rs) because that is the only layer
where the response's raw token texts (dropped by `analyzed_from`) and its
term vectors both still exist. The legacy pipelined-unary ingest fallback
(sidecars that predate AnalyzeStream) does not accumulate.

Sketches are exact ports of the Java reference: same FNV-1a + murmur3
finalizer base hash, same splitmix64 row derivation, same parameters,
same byte layouts (CMS table = LE u64 row-major, HLL registers = one byte
each). Snapshots are protobuf `VocabSnapshot` messages (the messages
already exist in the vendored `analysis.proto`), so Java-written and
Rust-written snapshots are interchangeable — the cross-language vector
tests in `src/vocab.rs` pin this (identical hashes, identical sketch
bytes, and a byte-identical 5,259,355-byte `VocabSnapshot` encoding;
vectors generated by running the sidecar's own classes).

## Configuration

Off by default; when off, the cost is one `Option` branch per analyzed
response.

| Setting | CLI | Env | TOML | Default |
|---|---|---|---|---|
| enable per shard | `--vocab=true` | `TURBOVEC_VOCAB` | `vocab` (top-level or `[[shards]]`) | `false` |
| docs per window | `--vocab-window-docs=N` | `TURBOVEC_VOCAB_WINDOW_DOCS` | `vocab_window_docs` | 1,000,000 |
| heavy-hitter K | `--vocab-top-k=K` | `TURBOVEC_VOCAB_TOP_K` | `vocab_top_k` | 1024 |

Requires an index path (demo shards cannot enable it). An unwritable
vocab directory degrades the shard to uncounted with a loud warning —
ingest is unaffected (analytics, not a ledger).

## Snapshot layout

`<index path>.vocab/snapshot-<seq>-<sealedEpochMillis>.pb`, mirroring the
WAL's `<index path>.wal/` convention. A window seals when it reaches
`vocab_window_docs` documents and on graceful shutdown (best effort); a
process killed mid-window loses only that partial window. Writes are
write-then-move, so a crash never leaves a half snapshot. Startup scans
the directory and resumes the history (metadata only; full sketches load
lazily when a drift comparison names a snapshot).

## Drift reading and aggregation

`examples/vocab_drift.rs` (read-only; never writes into the scanned
directory):

```text
# List a shard's snapshot history:
cargo run --example vocab_drift -- --dir=/data/shard-0.tv.vocab

# Drift between two windows (bare sequence numbers or file names):
cargo run --example vocab_drift -- --dir=/data/shard-0.tv.vocab --from=0 --to=3

# ... with embedding-OOV coverage of the TOKENS channel:
cargo run --example vocab_drift -- --dir=/data/shard-0.tv.vocab --from=0 --to=3 \
    --embeddings=/models/potion-base-8M

# Merge shard-level snapshots into one aggregate (coordinator-side
# aggregation; HLL and count-min merge cell-wise, heavy hitters merge by
# re-running space-saving over the combined lists):
cargo run --example vocab_drift -- --dir=/data/shard-0.tv.vocab --merge=0,1,2 \
    --out=/tmp/merged.pb
```

Per channel the report shows both cardinalities and their union, the
novelty rate `(|A∪B|−|A|)/|B|`, the Jensen-Shannon divergence (base 2)
over the union of the heavy-hitter lists with count-min fill for missing
counts, and — with `--embeddings` — the share of the newer window's token
mass absent from the model's `vocab.txt` / `tokenizer.json` vocabulary.
None of these gate anything; they inform the operator's decision to train
a candidate embedding reweight. Promotion is always decided by live A/B.
